# Engineering log

Brief reference of real bugs found and fixed while building this project — useful for interview talking points, not project documentation (see `CLAUDE.md` for that).

| Issue | Root cause | Fix |
|---|---|---|
| No token-by-token streaming | Only a blocking `/research` endpoint existed | Added `/research/stream` via `graph.astream(stream_mode=["messages","updates"])`, filtered to writer-node tokens only. Used `"updates"` mode (node-keyed) instead of `"values"` (snapshot-keyed) to detect critic retries — a score-delta heuristic would silently miss two genuine rejections that land on the same score |
| No Docker packaging | Never containerized | Multi-stage Dockerfile (`uv` builder stage + slim Python runtime, non-root user) |
| `/research` returned 404 from Pinecone | Index was never created, just referenced in config | Found via live testing against the real backend; created the index with the documented model/dimension/metric |
| One network blip killed the entire agent run | `web_search` tool had zero error handling — any exception propagated and crashed the whole LangGraph run with no response sent at all | Wrapped the Tavily call in try/except, return an error string to the LLM instead of raising |
| Redundant Pinecone calls every loop iteration | `researcher` re-ran RAG retrieval for every sub-query on every visit, even though the queries never change between loop iterations | Skip retrieval once `retrieved_docs` is already populated |
| Sub-query retrieval was fully sequential | Plain `for` loop over 2-4 sub-queries, one Pinecone round trip at a time | Converted `researcher` to `async def`, fanned out via `asyncio.gather` + `asyncio.to_thread`; also switched the LLM call to `.ainvoke()` — a sync call left inside an `async def` would've blocked the event loop for every other request |
| Requests could hang indefinitely | Two nested unbounded loops (critic→researcher retry, researcher↔tools tool-calling). Checked the installed LangGraph source directly — its actual default recursion limit is 10,007 (not the commonly-cited 25), so it offered no practical protection at this pipeline's latency | Added a single `steps` counter incremented once per `researcher` visit (the node common to both loops), checked by both routing functions, capped at `MAX_STEPS=6` |
| Live web search results never appeared in the final report | `researcher`'s LLM call sent a fresh prompt string each time, never the actual message history — so it couldn't see its own prior tool results. Separately, `writer` only ever read `retrieved_docs` (RAG hits), never message history at all, so Tavily results were structurally discarded | Passed full message history into the researcher's LLM call; extracted `ToolMessage` content into the writer's prompt directly |
| Dead code | `CriticOutput.should_retry` was generated by the LLM on every call but never read anywhere — routing only used `score` | Removed the field |
| Reports drifted off-topic whenever the corpus didn't cover the question | `writer` and `critic` were never passed `state["query"]`. The writer was told to "write the report based on the retrieved context" and had no idea what was asked, so it summarised everything handed to it — README setup instructions retrieved at similarity 0.198 became half a report about AI chips, `git clone` and `docker build` included. The critic then scored that report 0.85 and passed it, because it can't judge relevance to a question it was never shown either. Every unit test passed and the endpoint returned 200; the failure only became visible once the demo UI put retrieval scores and the report side by side | Passed the query into both prompts, and told the writer that low-ranked context is often unrelated and should be ignored rather than summarised. Same query re-run: 10 headings → 2 (`Nvidia`, `AMD`), zero setup-instruction leakage, critic 0.85 → 1.00 |
| No observability into a non-deterministic multi-agent pipeline | Nothing instrumented | Added LangSmith via env vars only — zero code changes, since LangGraph auto-instruments when `LANGSMITH_TRACING` etc. are set. Caught a real bug doing it: Docker's `--env-file` parser doesn't strip quotes like `python-dotenv`/shells do, so `LANGSMITH_PROJECT="Multi-Agent Research"` baked literal quote characters into the actual project name |
